## Recent Changes

- Bug fix (`context/current-issues.md`): unauthenticated visits to `/` (and logging out from `UserButton`) were redirecting to Clerk's hosted Account Portal (`https://<app>.accounts.dev/...`) instead of the local `/sign-in` page, and logout additionally threw `Failed to fetch RSC payload` in the browser console. Root cause: `.env.local` had lost the four `NEXT_PUBLIC_CLERK_SIGN_IN_URL`/`_SIGN_UP_URL`/`_SIGN_IN_FALLBACK_REDIRECT_URL`/`_SIGN_UP_FALLBACK_REDIRECT_URL` lines that `npx clerk@latest init` originally wrote (confirmed via `curl -sD -`: the server itself, not the client, was issuing the cross-domain 307). Both `proxy.ts`'s `auth.protect()` and `ClerkProvider`'s client bundle (`mergeNextClerkPropsWithEnv.js`) resolve their local sign-in/up destinations from those exact env vars with no other fallback, so losing them made Clerk fall back to the hosted Account Portal; the logout error was a downstream effect — `ClerkProvider` re-invokes the proxy via an RSC fetch to `/` on every auth-state change (`__internal_invokeMiddlewareOnAuthStateChange` default), and an RSC fetch can't follow a cross-origin redirect. Fix: restored the four env vars in `.env.local`; hardened `proxy.ts` to pass `unauthenticatedUrl` explicitly to `auth.protect()` (computed from the same `signInPath` constant, with `redirect_url` manually appended so the post-sign-in return-to-original-page behavior isn't lost); hardened `app/layout.tsx`'s `<ClerkProvider>` with explicit `signInUrl`/`signUpUrl`/`signInFallbackRedirectUrl`/`signUpFallbackRedirectUrl` props sourced from the same env vars — this is the exact override mechanism `mergeNextClerkPropsWithEnv` itself uses (props win over env), so the client bundle no longer silently loses this knowledge if `.env.local` is ever missing these lines again. Verified via `curl -sD -`: `/` and `/editor` now 307 to `/sign-in?redirect_url=...` (local, not accounts.dev); `curl`'d `/sign-in` HTML confirms the client Clerk config now embeds `signInUrl":"/sign-in"`, `signUpUrl":"/sign-up"`, `signInFallbackRedirectUrl":"/"` directly regardless of env state. `tsc --noEmit`, `npm run lint`, and `npm run build` all pass.

## Architecture Decisions

- The `shadcn` CLI resolved to v4.21.0, a notably different major version than classic shadcn/ui: it uses a "preset" system (chose **Nova — Lucide/Geist**, matching this project's existing icon/font choices), a unified `radix-ui` package instead of per-component `@radix-ui/react-*` packages, and a standalone `cn` npm package (drop-in `twMerge(clsx(...))` replacement) that `lib/utils.ts` re-exports from — this is the CLI's own generated convention, not hand-rolled.
- Removed the individually-installed `@radix-ui/react-slot|dialog|tabs|scroll-area` packages since the unified `radix-ui` package (added by `shadcn init`) supersedes them and is what the generated components actually import.
- `@clerk/nextjs` resolved to v7.9.2, which is Clerk "Core 3" — a major break from the Core 2 API this model was trained on:
  - `auth`, `currentUser`, `clerkMiddleware`, `createRouteMatcher`, and `clerkClient` no longer exist on the `@clerk/nextjs` root export (it types `auth` as `never` there); they must be imported from `@clerk/nextjs/server`.
  - `<SignedIn>`, `<SignedOut>`, and `<Protect>` are removed and now throw at render time (`removedControlComponents.tsx`) with a message pointing at `<Show when="signed-in">` / `<Show when="signed-out">` / `<Show when={{...}}>` instead. None of these were needed for this feature, but the next feature that needs conditional rendering by auth state must use `<Show>`, not the old components.
  - Themes moved from `@clerk/themes` to a new `@clerk/ui` package; import as `import { dark } from '@clerk/ui/themes'`.
  - `ClerkProvider` must be inside `<body>`, not wrapping `<html>` (a Core 2 pattern that used to be valid).
  - `createRouteMatcher` itself is deprecated in this version (in favor of resource-based auth checks) but still functional and is what `proxy.ts` uses, matching the "protect everything by default" pattern this feature calls for.
